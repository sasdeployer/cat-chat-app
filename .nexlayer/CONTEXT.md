## Notes from the analysis

- Three pods, one service each: frontend (Nginx + React build), backend (Node/Socket.io) and db (PostgreSQL 15). The database is never co-located with the app.
- The backend reaches the database at db.pod:5432. The Nginx config in the frontend must proxy /api and /socket.io (with WebSocket Upgrade headers) to backend.pod:<backendPort>, not to localhost or a bare hostname like 'backend'.
- The backend port (5000 here) is inferred because the README is truncated. Confirm it against backend/Dockerfile or nexlayer.yaml and update the pod port and PORT env var to match.
- The repo has its own Dockerfiles for each tier. Any database init SQL from database/ must be baked into the DB pod image or run by the backend on boot, since the pod uses a stock postgres image here.
- Database credentials are generated by Nexlayer, so the placeholder password is only illustrative.
- Socket.io needs WebSocket support through the proxy. If the backend is ever scaled to multiple replicas, it needs sticky sessions or a Redis adapter.
